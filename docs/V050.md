# Nass v0.5.0 — acquisition adapters

This change adds **optional** acquisition routes. No credentials, paid API, proxies,
untrusted redirect chains, or circumvention of private-video access are introduced.

* Set `NASS_INVIDIOUS_URL=https://your-trusted-instance` to attempt captions via
  Invidious after native caption methods fail. The instance sees the public video ID.
  API listing URLs are ignored; all requests are reconstructed on the configured origin.
* Set `NASS_ENABLE_MWEB_POT=1` **only after** a compatible yt-dlp PO Token Provider
  is independently configured and tested. This enables an initial mweb attempt.
* Call `nass_acquisition_report` for a configuration/dependency report; **not** a live
  health check. Provider success must be confirmed from actual per-job attempts.
* Original paths remain available if either new route fails. Invidious does not
  transcribe video lacking captions.

Reference: https://github.com/yt-dlp/yt-dlp/wiki/PO-Token-Guide
Reference: https://docs.invidious.io/api/

## Acceptance checklist

1. Run `python -m pip install -e '.[test]'` and `pytest -q`.
2. Run 3 video classes: manual captions, auto-captions and public captionless.
3. Record `nass_job_status`, `nass_get_transcript`, audio source, timing,
   and every provider attempt in a private acceptance report.
4. Compare an actual Arabic audio excerpt against returned words manually.
5. No deployment to Render until verified and reviewed; cloud-IP errors may remain.

**Critical limitation**: this is source code + tests, not proof of live YouTube access.
